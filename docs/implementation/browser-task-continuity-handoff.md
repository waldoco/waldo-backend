# Bounded public browser task continuity handoff

Base: verified beta-mvp 79ebd2de7d2b8d2f1a5e6707d3ef1a8be416a5b7. No provider activation or deployment is included.

## Implemented seam

`browserTaskHandler` wraps the existing `browse_act` handler. Calls without `command` retain legacy behavior. Strict typed commands are inspect, fill, prepare_submit, verify, cancel. There is no model-supplied final submit, owner ID, provider session ID, credentials or direct approval. Typed calls without a configured task host fail closed without legacy/provider fallback.

`browserTaskContinuity` is the production host factory. Supply a canonical owner/task exclusive store, trusted provider driver, exact immutable manifest digest and current host `admit` grant ledger. The store holds parsed checkpoint metadata including private provider session identity; never project its raw row into a prompt or trace. Grant validation must include action/target/state/binding and desk approval reference, and run immediately before each physical operation. The driver port permits site-specific authoritative confirmation; model extraction is not confirmation.

`publicFixtureBrowser` is a complete concrete Cloudflare Playwright 1.3.6 driver for the controlled, self-contained, non-hostile HTTPS form. It uses guarded acquisition, the public SDK `connect` endpoint with persistent=true, the dedicated persistent default context, native observed form controls and exact final synchronous snapshot checks. It never calls the SDK fresh-allocation reconnect wrapper. Native form actions require exactly the configured text/email inputs and a submit button; submit overrides/additional associated controls are rejected. This is deliberately not an arbitrary hostile-page or login engine.

## Activation blockers and limits

Current source has pinned @cloudflare/playwright 1.3.6, but wrangler has no BROWSER binding or nodejs_compat. Activation requires explicit binding/runtime configuration, read-only entitlement/cost assessment and authorized budget, unique public HTTPS controlled fixture, and separately recorded live reconnect/form/receipt/cleanup evidence. This patch does not add credentials, account setup, new permissions or egress domains. HTTP/HTTPS domain guardrails plus origin/protocol/port checks do not establish universal network isolation. Page-realm native prototypes are used only in the trusted fixture scope; hostile-page resistance and isolated execution world remain unproved.

## Release owner host integration checkpoint

The integration branch now constructs `browserOwnerHost` inside the actual `TelegramOwnerDO`, replaces the existing `browse_act` registration with the single composite, and connects continuation approvals to the desk bridge. It persists the checkpoint in the private owner DO, verifies the physical DO and fresh strict canonical directory binding on every admission, validates exact current operation evidence and the locally claimed desk row, fences `/stop` before provider/mutex waits, and adds browser expiry/cleanup retry to shared alarm arbitration as a fourth fair work kind. Cleanup runs through coalesced background maintenance, preserving inbox/transport/scheduler service. No SQLite transaction spans provider I/O.

One task is admitted per owner configuration. Lifetime remains 10–600 seconds (default 60), preparation/submission is bounded to five attempts, and at most 32 fresh operation authorizations are persisted per owner task, including before-operation checks. Reconstructing the service cannot replenish this count. A closed task cannot allocate again. Provider allocation uncertainty and cleanup failure remain visible in the private checkpoint. The grant supplier is an independent trusted host port, not a model/page callback; this checkpoint supplies no production grant ledger or provider binding.

Wrangler's two-argument constructor receives no browser configuration, so typed browser requests remain disabled. The optional private fourth constructor argument is exercised by synthetic authenticated DO tests. Production activation still needs a reviewed code configuration factory, canonical serving owner identity (the legacy owner-turn fixture principal fails exact matching), independent current grant source, Cloudflare BROWSER/runtime support, controlled HTTPS fixture, approved spend bounds and live reconnect/receipt/cleanup evidence. No flags, Durable Object namespaces, provider permissions or deployment are changed here. Local evidence does not establish concurrent live multiuser signup, global account concurrency or account spend enforcement.


Browser cleanup recovery is bounded to three physical end attempts per task, durably counted before each provider call with 30-second automatic retry spacing. Exhaustion retains `cleanup_pending`, the private provider identity and a private exhausted receipt while removing the runnable retry wake. Lost allocation identities, unavailable drivers and incompatible configured session lineage likewise retire wakes with unresolved status; provider TTL remains the physical bound, and none certifies closure. Missing/malformed checkpoints clear stale due slots and fence the configured task; malformed bytes remain in place with private quarantine metadata. Already-closed checkpoints clear stale wakes without repeating cleanup.
