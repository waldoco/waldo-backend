- `run-journal/outbox-runtime.ts` is imported only by `tracer/tracer-do.ts` and `run-loop/do.ts` — not reachable from owner turns. `[reported]`
- `OutcomeModule` (Outcome/Mission/WorkUnit) and `work-unit-execution.ts` are not reachable from the serving path. `[reported]`

**Rule conflict.** CLAUDE.md: "One per-owner authority root… no competing agent brain. Keep `WaldoCoordinator`, the trusted RunLoop/physical effect path, and existing ContextComposer."

**Docs.** `docs/planning/CHANNEL_ADAPTER_EXTRACTION_2026-10-02.md:58` names the choice ("fold the Telegram turn path onto the run loop, or … retire or park the run-loop stack") and §7 lists "which core wins" as undecided. `PER_USER_PRODUCTION_MODEL_2026-09-30.md:50-51` and `NEW_DEVELOPER_GUIDE_2026-09-28.md:9` treat `TelegramOwnerDO` as the owner-state boundary. No ADR backs either. `[reported]`

**Impact.** Intent-before-I/O, keyed reconciliation, one retry owner and Outcome closure exist in contracts and RunLoop but not on the path users hit. R4 and R5 are largely consequences.

## R2 — Unbounded background-wake context (#787 hypothesis)

**One prompt builder, several callers.** Owner chat, standing-order fires, legacy event briefs, update cards, mail follow-up, day cards and reminders all go through `responder.prompt` → `converse` → `JoinedConversationPath` (`owner-turn.ts:625-637`; callers `telegram-owner-do.ts:1880,2112,2141,2148,2189`, `owner-turn.ts:948`). Card content is the user message and is persisted into conversation history (`owner-turn.ts:739`). `[reported]`

**Day-card input** (`telegram-owner-do.ts:2184-2187`) `[verified-source]`:
- `updates.unfolded()` — `SELECT … FROM update_cards WHERE folded = 0 ORDER BY at`, **no LIMIT** (`channels/update-cards.ts:61-65`).
- `today: transcript(episodes.since(midnight, 30_000), …)` — up to 30,000 chars.
- `ledger` — includes `loopsSection`, unbounded `[reported]`.

**Cap.** Messages sanitiser `max_chars: 32_768` (`../contracts/src/memory/sanitise.ts:58`). The soft-oversize fallback reduces to the last message only when `request.messages.length > 1` (`llm/provider.ts:1416`) — a single oversized card message has no fallback. `[verified-source]`

**Ratchet.** `updates.fold(now)` runs only after a successful send (`telegram-owner-do.ts:2193`). A failing card never folds, so the next card is larger. `[verified-source]`

**Misclassification.** OpenAI adapter maps HTTP 400 → `invalid_args`; context-length errors are 400s (`llm/openai.ts:157-165`). `status==='incomplete'` is labelled `oversize` (`openai.ts:75-76`). `[reported]`

**Secondary hazard.** `updates.unfolded()` is evaluated before the `try` (`telegram-owner-do.ts:2186` vs `2188`); it does `JSON.parse(row.changes)` then `changeLines(...)`. A row purged to the bare string `"[forgotten]"` (§3, `claims.ts:475` path for non-JSON `changes`) would likely throw outside the handler. `[inference]`

**Only one wake has a pre-call budget:** `planDay` via `composeDayPlanInput` (#734, `day-cards.ts:156-170`). `[reported]`

**Window vs sanitiser mismatch.** History window budget 100k tokens (`window.ts:15-27`) versus sanitiser 32,768 chars — no shared contract. `[reported]`

**ContextComposer.** Runs on every submit as a gate (`joined-path.ts:60-61`) but uses a hard-coded `WALDO_ENV:'local'` composer (`owner-turn.ts:191` → `run-loop/adapters.ts:153`); its prompt is used only when a canonical binding exists, never for background `prompt`. In production `canonicalPreparation` is false (`telegram-owner-do.ts:213`). `[reported]`

**Falsifier.** Read `halted_by` / `scribe` on the failing day-card trace (`owner-turn.ts:298`). If the halt is not `scribe:oversize`, this hypothesis is wrong and the provider path must be diagnosed instead. The tracker's warning ("don't assume overflow") stands until that is read.

## R3 — Forget: stuck hold, history truncation, held candidate defects

### R3a. Incomplete forget truncates history and memory
- `owner-turn.ts:579`: `forgettingState?.incompleteTopics().length ? [...request.messages.slice(-1)] : …` `[verified-source]`
- Also empties memory claims/recall (`owner-turn.ts:444-447`), refuses retained-read tools (`:491,:503`), withholds orders/loops carrying the topic (`:585-590`). Applies to background wakes. `[reported]`
- Coverage starts incomplete immediately (`claims.ts:757`, `beginTopicCoverage`). `[reported]`

### R3b. `update_cards` has no exit
- `update_cards` is not offered to the span selector (`collect` list, `claims.ts:706-717`). A card carrying the topic sets `local.incomplete` → `sources_incomplete` → selector never runs → no spans → `purge` returns early for coverage ≠ 0 (`claims.ts:352`) → hold persists. No code deletes `update_cards` rows. `[reported; mechanism inferred from cited lines]`
- **Consequence:** R3a then applies indefinitely. This is the most plausible source of "a stuck forget cuts history to the last message" and of the standup-context failure (A3).

### R3c. Defects in f38971d5 (#796), source-confirmed
Source confirmation of Core's 18:03 triage; **not** a reproduction of Dalda's unseen fixtures.

### R3d. Three matchers, not one
- Hold: SQL `projectionPredicate` (LIKE + `json_tree` values + keys) over `likePrefilter(topic)` (`claims.ts:108-111,737`).
- Purge exit: JS `prefixTied` (lowercase + `jsonLeaves`) (`claims.ts:113-117`) over selected spans + claim text.
- Readback: `exact` over `stringsOf` — values only, ignores keys (`claims.ts:162-165,628`).
- Hold searches the bare topic; purge searches spans (`forget_topic` set null, `owner-turn.ts:851,856`). `[reported]`
- One unparseable `update_cards` row, even unrelated, makes readback throw, so every purge stays not-ready (`claims.ts:632`). `[reported]`
- `projectionValueHolds` has no production caller since #796 (`held-rows.ts` no longer filters). `[verified-source via diff]`

### R3e. Gaps in Core's planned single-PR correction
The plan (shared whole-card matcher, no 40-char constant, preserve schema/join keys, blank values) does not by itself:
1. Add an exit for `update_cards` (R3b).
2. Preserve unrelated text inside a mixed card — "blank all values" still erases it. Needs leaf-level blanking of topic-bearing leaves, with hold (not blank) when the topic spans leaves.
3. Make readback check keys and tolerate unrelated unparseable rows.
4. Guard day-card rendering against purged rows (R2 secondary hazard).
5. Resolve the unsupported-representation outcome: Core proposes "not hold"; Dalda asks "remain unresolved". Source cannot settle it — owner/reviewer decision. #794 stays open.

## R7 — Fixed rules making judgment calls

CLAUDE.md bans regex/fixed rules for judgment calls (tone, intent, topic, what to remember) outside hard security boundaries.

| Rule | Location | Judgment it makes | Disposition |
|---|---|---|---|
| `looksTransient` | `memory/claims.ts:144-155` `[verified-source]` | What not to remember (questions, imperatives, "today"+errand verb). "use my work email for invoices" matches `^use (your\|the\|a\|my)` and is discarded. | **block** — move to model |
| `FORGET_INTENT` | `memory/claims.ts:87-88` `[verified-source]` | Whether the owner asked to forget; English-only, gates model-proposed forgets and turn mode (`claims.ts:1015`, `owner-turn.ts:767,918`) | **warn** — comment justifies as destructive-action guard; fails paraphrase/other languages |
| `correctionTopicMatches` | `memory/claims.ts:990-999` `[reported]` | Whether a correction replaces an old fact (word overlap) | **block** — topic judgment |
| `ciRedact` 3-char substring | `memory/claims.ts:76-77,373` `[reported]` | Topic matching without word boundary ("Sam" hits "Samsung") | **warn** |
| Whole-card blank on prefix | `memory/claims.ts:470-476` | Relevance of a card to a topic | covered by R3 |
| `IRREVERSIBLE` keyword list | `tools/live/browser.ts:131-137` `[reported]` | Which browser clicks need approval | allowed (safety) but false positives on "post", "order", "book", "remove" |
| `RECALL_STOP_WORDS` | `memory/claims.ts:805` `[reported]` | Retrieval heuristic | low |

Allowed: medical dosing gate (`scribe/medical-gate.ts`), sanitiser secret/health patterns (`scribe/sanitiser.ts:54-102`), OTP hygiene, structural event enums.
