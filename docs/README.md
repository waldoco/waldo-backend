# Waldo Backend Documentation

The live documentation tree is intentionally small. Start here:

1. [Product capability matrix](./planning/WALDO_PRODUCT_CAPABILITY_MATRIX_AND_THESIS_VALIDATION_2026-08-04.md) — product position, promised capability envelope, and value falsifiers.
2. [Architecture lock](./planning/WALDO_ARCHITECTURE_LOCK_AND_WHOLE_PRODUCT_BUILD_DIRECTION_2026-08-05.md) — current ownership, invariants, workstreams, and build authority.
3. [Final Home + Work architecture](./planning/WALDO_FINAL_HOME_WORK_BACKEND_ARCHITECTURE_PLAN_2026-08-04.md) — source-pinned current/target design, contracts, state machines, and migration.
4. [Next session plan](./foundation/NEXT-SESSION-PLAN.md) — repository implementation entrypoint.
5. [Next backend prompt](./foundation/NEXT-BACKEND-SESSION-PROMPT.md) — first bounded responsibility-handshake implementation task.
6. [Contributor onboarding](./foundation/CONTRIBUTOR-ONBOARDING.md), [operating workflow](./foundation/AGENT-OPERATING-WORKFLOW.md), and [verification pipeline](./foundation/LOCAL-DEV-TESTING-PIPELINE.md).

`planning/` contains current architecture plus source notes. `foundation/` contains current contributor and verification guidance. A plan or source note never proves implementation.

Completed ticket handoffs, wave plans, superseded product/app plans, generated work plans, and one-off verification logs are intentionally removed from the live tree. Git history preserves that evidence. Restore historical material only when a current debugging or migration need justifies its maintenance cost, and label it non-authoritative.
