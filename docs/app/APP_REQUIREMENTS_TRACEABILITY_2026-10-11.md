# App requirements traceability: app slices and open questions to backend gates

Draft, 11 October 2026 (read 10 October 18:30 to 18:45Z). Docs only. It decides nothing, merges nothing, deploys nothing and claims no capability.

This file answers one question per row: what must the backend provide for this app slice, where does the ledger plan it, what carries it in the contracts, what serves it today, who owns the next step, and what must happen next. It does **not** restate ledger status and is not a second plan. The single backend plan is [the website promise ledger][L], owned by the gap-analysis session. A ledger link points at a section and a promise name; the ledger has no row ids. The app side is [the app build order][AB] (slices N1 to N9, B1 to B10).

## Evidence key

- **V** = verified by the author of this file: file and line at a stated SHA, a PR state read with `gh` at a stated time, or a live response.
- **I** = inferred: relayed by another session or document, or reasoned, and not read here. Every I names where it came from.

A route counts as **served** only when the runtime dispatches it in source at the deployed release **and** a signed-in read has returned the contract shape. This file only ever reaches the first half. No signed-in read was run.

### What `/app/v1` dispatches today (V, source at `fec37a43` = `a7b80436`)

`POST auth/code`, `POST auth/verify`, `GET session`, `POST auth/signout`, `GET chat/main`, `POST chat/main/messages`, `GET chat/main/messages/{client_message_id}` (the receipt, forwarded to the owner DO), `GET controls`, `POST actions`, `GET actions/{request_id}` (`channels/app-api.ts`, `channels/app-controls.ts`).

Three limits inside the served set (V):

- `POST actions` accepts `view: 'day'` only; any other view returns `400 invalid_action` (`app-controls.ts:43`).
- `GET controls` returns `503 projection_unavailable` when the built projection does not fit the contract (`app-controls.ts:38`).
- `GET chat/main` builds every message as one `text` part and sets no `visibility` (`app-api.ts:177`, `appTranscriptPage`).
