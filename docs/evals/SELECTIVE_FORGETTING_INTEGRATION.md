## Privacy and scope

Selection is bounded to at most 64 exact ASCII-topic source representations in an 8 KiB envelope and 32 exact spans of 12..4096 characters. Host rechecks source bytes and admission before custody/mutation. Completion requires supported source readback and appropriate witness custody. Unsupported/truncated/changed/foreign representations stay coverage-incomplete with original bytes preserved. Internal forget/writer model logs contain metadata only. No markerless global erasure, provider retention erasure, whole-turn deletion or repair of already-orphaned residues is claimed.

There is one additional logical model call for supported forgetting on the existing serving model. No stronger model, automatic retry loop, provider grant or billing configuration is activated. SK5's real referent diagnosis remains pending the exact failing provider instructions and a known-cost isolated comparison; this source release does not claim that fix.

## Recovery and rollback

The existing topic_purge_pending table gets additive coverage_incomplete state: 0 exact literal retry, 1 unproved owner intent, 2 selected coverage awaiting verification. States 1/2 cannot settle merely because a literal marker is absent; only an explicit owner retry with complete supported stable evidence may retire selected coverage. Pending values clear only after verified settlement; durable re-admission barriers remain hashes.

Do not roll back to an incompatible older reader while state 1/2 rows exist: older code ignores this column and can resume marker-only cleanup. Preserve namespace identity and use a compatible forward correction if rollback safety is not established. This is a local storage/runtime compatibility limit, not permission for broad production cleanup.
