# Curated active skills

Why build this: serving c1f700b4 has a validated loader but no active owner procedures. An owner cannot install a reviewed reusable document/email workflow, select it for a task, or revoke it. Build one instruction-only catalog procedure; reuse skills SQLite rows, RuntimeSkillLoader, prompt serializer and owner safeguards. This adds capability without remote downloads, scripts, arbitrary workspace activation, grants, or self-learning.

Primary patterns inspected 2026-10-03: https://learn.chatgpt.com/docs/build-skills (metadata-first selective instructions, instruction-only default, enable/disable); https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview (progressive disclosure and trusted sources). Adapt instead of copying filesystem scanning because workspace files remain untrusted data.

Use strict skills_list/install/disable/load tools. Install/disable are user_message-only and taint-gated; the host must bind explicit owner lifecycle authorization. Catalog identity is name, integer version, reviewed source reference and canonical content. Persist enabled catalog rows in existing skills table; never use stored body as authority unless exactly catalog-identical. Model-selected invocation state holds only name/version. Bodies are not tool output or conversation history: each model step reloads the selected enabled row through the existing loader, enforcing its budget and rendering fences, and attaches trusted procedure under owner safeguards. The ordinary canonical context remains empty-skills; only an explicit typed host capability supplies procedures. Disable takes effect before the next model step and on all later turns; selections do not persist.

Acceptance: fake-provider owner path selects procedure, produces/revises practical draft through existing workspace tools across separate turns, retains file identity/revision, never sends it or acquires tools. Unknown versions, tampered body/catalog source, budget failure, wrong owner, externally derived lifecycle arguments, revoked/closed run, background installs and disabled skill must reject. Actual-model/live execution remains separate evidence.

Alternatives: eager loader binding is smaller but loads irrelevant bodies for every user_message; direct skill tool body output retains instructions in history after disable. Both rejected for this slice. Conservative UTF-8-byte budget is acceptable only explicitly labeled a upper-bound estimate, not exact tokens, with its assumptions documented and count failure closed.

Implementation refinement: default serving legacy Telegram gets a typed private bridge over its existing verified owner inbox/current run, with actual Telegram custody pin. Canonical empty-skill assertions stay unchanged. Initial lifecycle UX is exact developer/test commands; natural-chat/console explicit approval remains a follow-up.
