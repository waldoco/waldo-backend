## Reconciled architecture facts

### Read and write discipline

- [observed] ADR-0005 fixes exactly five halls and makes Scribe necessary for the hall ACL boundary. Its later amendment allows truth-driven supersedence only through Scribe, never through a new writer. [ADR-0005](</Users/shivanshfulper/Developer/Pin4sf/waldo-brain/01-Waldo/Architecture Decision Records (ADR)/0005-five-typed-memory-halls.md:6>)
- [observed] ADR-0006 forbids direct writes to `memory_blocks`; after the accepted amendment, retrieval may union committed blocks with Scribe-sanitised pending inbox entries, and the nightly Scribe remains the only promotion path. [ADR-0006](</Users/shivanshfulper/Developer/Pin4sf/waldo-brain/01-Waldo/Architecture Decision Records (ADR)/0006-scribe-inbox-merge-not-direct-writes.md:49>)
- [observed] ADR-0024 defines one ordered, fail-closed Scribe sanitiser seam and specifies that rejected memory writes are dropped and never retried. [ADR-0024](</Users/shivanshfulper/Developer/Pin4sf/waldo-brain/01-Waldo/Architecture Decision Records (ADR)/0024-scribe-sanitiser-canonical-spec.md:28>) [failure handling](</Users/shivanshfulper/Developer/Pin4sf/waldo-brain/01-Waldo/Architecture Decision Records (ADR)/0024-scribe-sanitiser-canonical-spec.md:191>) The current `prepareWithScribe()` uses that existing implementation and validates both pre- and post-sanitisation shapes. [prepare.ts](../../../packages/runtime/src/scribe/prepare.ts)
- [inference] HEY-15's reader must consume the Scribe admission result as a precondition rather than call `sanitise()` again. A second reader-side sanitiser would duplicate policy, obscure the write-time audit decision, and violate the single-seam rule.

## Historical baseline conflicts and decisions before code

1. [conflict] **Presentation ownership is not fully represented by the existing dependency seam.** The ticket requires fenced output; the pure contract renderer requires `(RecallResult, conflicts, authority)`, while `PromptBuilderDeps` provides only `recall(ctx, hint?)`. Do not hide conflicts in mutable gateway state or silently omit them. Before implementation, select one explicit, concurrency-safe handoff: a private H15 presentation/read aggregate consumed by H16, or a narrowly reviewed contract expansion. H15 must not begin prompt composition itself.

2. [conflict] **`partial` status exists but ADR-0031's reference fan-out is all-or-nothing.** Its documented `Promise.all` failure path returns three empty arrays, while `RecallStatus` also permits `partial`. The safe first implementation is all-empty + `failed` for any source failure, preserving the accepted behavior; partial results need an explicit subsequent decision and tests.

3. [conflict] **The row schema is not proof of Scribe admission.** `rejected: false` is necessary but does not by itself prove that a caller used `prepareWithScribe()` before persistence. A read-source boundary must own that proof. Do not fix this by a second sanitiser, a raw-inbox fallback, or a new universal row/body cap.

4. [blocked] **FTS remains a decision, not a default edit.** The local schema is at its HEY-144 V2 migration and no FTS table exists. The coordinator must first admit a file manifest and decide whether fake-source orchestration can land without a migration or whether an additive internal FTS migration is needed after the required rebase. Supabase/external migration is out of scope either way.

## Historical initial implementation recommendation — superseded

[proposed] Admit HEY-15 as a read-only, fake-first runtime slice only after a coordinator-approved ownership manifest resolves the four items above. The first implementation should:

1. Create one injected, owner-scoped **read source** behind the runtime gateway. Its postcondition is: active committed blocks plus only Scribe-admitted, non-rejected pending rows; no raw inbox body, raw health, prompt, secret, storage key, or direct SQLite access leaves that module.
2. Use the existing `RECALL_CONFIG`, query builder, schemas, `dominates()`, hall/domain authority, and canonical `renderRecall()` rather than copying their policy or creating a second sanitiser/renderer.
3. On a non-skip trigger, fan out to the injected memory, episode, and V1-empty evolution legs with the ADR-0031 limits. On a skip trigger, make no source call and return the canonical empty result with `duration_ms: 0`.
4. On any source/validation failure, return the canonical all-empty `RecallResult`, continue the invocation, and emit only a bounded status/category through an injected telemetry seam. Never record exception text, query text, result content, identifiers, health data, or prompt text.
5. Preserve the strict boundary: no memory write, Scribe merge, Scribe policy change, R2/provider/binding/configuration work, prompt assembly, RunLoop wiring, or live side effect. Do not add an FTS migration until it is separately admitted.

## Historical acceptance-focused fake test matrix

- [proposed] Per-trigger configuration and query construction: exact selected halls/windows; 800-character cap; derived zone wording only; no source calls for `handoff_act` or `dreaming_mode`.
- [proposed] Source arguments and bounds: owner scope, active-only committed default, memory limit 5, episode limit 3, V1 evolution limit 3, and no rank fields in prompt-destined hits.
- [proposed] Union-read admission: a Scribe-admitted pending row can surface with its code-stamped provenance; rejected, raw/unadmitted, wrong-owner, superseded, malformed, or raw-health-looking candidates cannot surface.
- [proposed] Trust and conflict goldens: renderer delegates to the existing `dominates()` and real hall/domain predicates; it never labels an inadmissible update stale, never hides the committed side, and caps conflict pairs at the existing bound.
- [proposed] Fencing: canonical `<recall>` output and marker are byte-stable; no duplicate renderer or renderer-side sanitiser exists.
- [proposed] Failure: each leg throw/reject/invalid result returns all-empty and a content-free `failed` outcome without throwing; no raw exception/query/content reaches fixtures or telemetry. A future partial-result case remains excluded until a decision changes the ADR-0031 behavior.
- [proposed] Boundary regressions: no `memory_blocks`/`memory_inbox` write, no schema version change, no provider/R2/binding/RunLoop/prompt-builder call, and no external side effect under fake-source tests.
