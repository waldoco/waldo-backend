# Invite signup phone proof — proposal only

Owning issue: https://github.com/waldoco/waldo-backend/issues/496. Existing provider assessment: #158. This document does not authorize provider setup, SMS, invitations, hosted SQL or deployment.

The current implementation prepares recipient-bound fragment links, verifies email and retains a 15-minute signed continuation with an invite hash. Phone collection remains `not_configured`, unverified and incomplete. No new owner is created, no owner session is granted and no invite is consumed. The continuation contains no Supabase access/refresh tokens. It is browser-scoped temporary progress, not durable onboarding; deleting cookies or expiry requires email verification again. Existing bound owners retain signin through the canonical empty-phone branch.

The September 28 invite-chain SQL supersedes open signup. It checks email + hash + expiry/revocation/use and atomically consumes on owner creation. Its current signature accepts an unverified phone, so it cannot itself establish the new two-proof target. Runtime signin now passes empty phone to refuse new provisioning. Its one-use lock, auth-user ownership, duplicate identity rollback and existing-owner idempotency stay unchanged. Exact failure reasons are intentionally generic because `signin_allowed` returns only a boolean.

Before enabling completion, approve a provider and a contract that binds the phone challenge to the same verified Auth user, recipient email, invite hash and exact normalized number. Proposed durable pending identity/challenge state must survive retries, expire, cap attempts, serialize verification and retain failure evidence. Phone proof is independent of channel pairing and must not enable phone signin, create a second Auth user, merge owners by phone match, or accept client-asserted verification. Provider responses, timeouts, duplicate callbacks and response loss need authenticated receipts and reconciliation; no blind SMS retry after an unknown send outcome.

Propose an additive atomic completion function that validates both proofs and their expiry, rechecks the live invite, creates at most one owner with authoritative phone verification evidence, stamps precisely that invite, and opens access only afterward. Reuse the current invite UPDATE lock, unique identity constraints and transactional rollback. Never move consumption into entry GET/HEAD, send-code or email-only verification. No SQL change is included in this PR; review the full DDL/ACL/HMAC signature, same-user constraints, continuation invalidation and local pgTAP concurrency cases before approving it.

Provider acceptance must name availability, country coverage, rate limits, retry owner, fraud/cost bounds, consent, custody, delivery evidence and revocation. #158 remains design-only and is not an approved SMS adapter. End-to-end signup is blocked until that contract is approved and separately implemented/tested. Live email template delivery, SMS delivery, hosted schema and account acceptance are not proven by this local proposal.

Rollback of this slice: close the unmerged draft PR. After a future merge, reverting the runtime signup flow must not restore new-owner provisioning with unverified phone; preserve the empty-phone signin gate. There is no hosted mutation to undo.
