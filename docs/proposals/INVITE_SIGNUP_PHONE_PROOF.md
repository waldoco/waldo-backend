# Invite signup: verified email and optional contact

Owning issue: https://github.com/waldoco/waldo-backend/issues/496. The owner explicitly changed the membership requirement: phone stays visible but is optional. Verified email and a valid recipient-bound invite suffice. This disposition replaces the earlier proposal to block membership until SMS proof. It does not authorize hosted SQL, provider setup, SMS, real invitations/accounts or deployment.

The runtime verifies the Supabase email OTP, requires the matching confirmed email and Auth subject, and seals a 15-minute continuation containing only an invite hash, Auth subject, email and optional unverified contact. Finish signup uses a distinct signed `signup_owner_for_auth` RPC; legacy `owner_for_auth` and its existing-only runtime sign-in call remain unchanged. The new SQL checks confirmed matching `auth.users` identity, admits only the exact live one-use invite for new owners, and transactionally consumes that invite with owner/settings creation. Already-bound identities resolve the same owner for safe completion retries. Bootstrap email-only claiming is excluded.

Blank phone is stored as NULL. Supplied phone is normalized E.164 contact only, never an authentication or account-link key. No `phone_verified_at` is set and the existing WhatsApp verified-phone trigger remains unchanged. Existing owners' contact/settings are not overwritten by retry. Auth-subject, live-email and DO uniqueness remain authoritative. Same-subject calls serialize; collisions roll back invite consumption.

Completion grants the resolved owner's console access and opens its existing server-backed session, then sets both Secure HttpOnly SameSite=Strict console/owner cookies and clears signup progress. Grant/session failure or unknown RPC response retains verified progress and entered contact so the user retries Finish without replaying an already-consumed OTP. The signed progress is readable bearer authority, not encrypted, device-bound or server-revocable. Anyone holding a copy can finish/retry until expiry. Restart clears this browser only; expiry requires email verification again.

GET/HEAD, OTP requests, email verification and Save contact never consume an invite or create a Waldo owner. Origin, CSRF, per-email/IP rate limits and signature checks stay fail-closed. OTP send, verify, contact save and completion have distinct per-email buckets; OTP limits remain unchanged. Console grant fetch and body decoding share a 10-second timeout. Invite denial remains generic. Resend retains the signed recipient/invite context and original deadline. OTP requests may create a Supabase Auth identity, which is distinct from a Waldo owner.

Local fixture tests cover email-only completion, optional contact, refusal gates and session/response failure recovery. SQL tests cover proof, invite states, uniqueness, replay, permissions and rollback. Authenticated hosted email delivery, applied schema, actual two-owner browser isolation and deployment remain separate release evidence. The additive migration is a local proposal until exact review and owner approval; no previously approved migration batch covers it.

Rollback: revert runtime completion and optional-contact wording to disable new signup while keeping existing-owner sign-in. Reverting runtime does not require deleting owners or reverting the additive RPC; any hosted rollback is owned by the release executor and needs its own reviewed instructions.
