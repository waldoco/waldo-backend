**Main-chat 503 (open, highest priority).** For the owner's account, `GET /app/v1/chat/main` answers 503 on every open. Controls, day, approvals and scores load in the same session.
- **Cause class, captured by L1 on staging `726ad0e7`.** Two requests (around 20:10:20Z and 20:10:29Z, L1's clock) each logged exactly `{"hop":"app_history_read","ok":false,"code":"history_invalid"}`. The DO event shows outcome `ok`, no exception and about 7 ms of CPU [inferred from L1's report].
  - So it is a stored-data fault in the owner DO's canonical history: a row fails the shape check in `canonical-owner-store.ts` `validate()`.
  - It is not a resource kill and not the session.
- **Why current code can't write that row** [verified in source at `beta-mvp` `c3b17f6a`]:
  - every canonical writer goes through `save()`, which validates first;
  - redaction (`conversation-store.ts` `redactConversationEntries`) and `scrub()` keep every field;
  - the validator hasn't changed since the store was created (`e35d0262`).
- **Leading hypothesis** [inferred]: the row was written by a build deployed to staging that never merged (the Mac lane deployed branch builds), for example #998's thread code at `fc4c2b9d`, or pre-squash commits of the PR behind `e35d0262`.
  - Check: for each staging Worker version on record (`fec37a43`, `81c4f892`, `15134581`, `726ad0e7`) and for `fc4c2b9d`, use `git merge-base --is-ancestor`, then diff the canonical validator and writers.
  - What we're after is the clause the old rows fail.
- **Scope question.** App sends probably fail too: app turns read history through the same `load()`, and `save()` re-validates the previous leaf's entry.
  - Confirm from source, then fix both read and send.
- **Fix in progress:** branch `l2/app-history-skip-invalid-rows` at `0692b4b2`, from `beta-mvp` `21a70277`, pushed. The PR opens after the gates pass [verified local equals remote].
  - It adds `readForDisplay()`, used only by the main-chat GET, which skips shape-invalid rows that match their witness and logs `history_rows_skipped` with the failed check and a count.
  - Strict `load()` for turns is unchanged.
  - Found while building it [verified by a probe]: `stableJson` throws `provenance_invalid` on any `undefined` value. So a skipped row is compared with its witness by plain JSON equality.
  - No current writer sets an explicit `undefined` field (`owner-turn.ts:580`, DO `:593`, `joined-path.ts:90`).
- **Fix direction** (the advisor agrees):
  - make `load()` skip only rows that match their witness but fail the shape check;
  - log a count and the failed clause from a fixed list;
  - keep owner mismatch, witness mismatch and duplicate ids fatal.
- **Edge cases needing red tests:**
  - a skipped row that is a parent (the tree on the turn path);
  - a skipped row that is the leaf. A code fix may not be enough there; a reversible quarantine of the owner's row is an owner decision.
  - The owner may see gaps where old rows are skipped. Say that in the PR.
- **Acceptance:** with L1's tail up, the owner opens Main chat and gets 200 with history, then sends one app message successfully, and no new `app_history_read` line appears.

  - runtime `npx vitest run` plus `--config` with `vitest.console-ticket.config.ts`, `vitest.common-bootstrap.config.ts` and `vitest.owner-ingress.config.ts`;
  - contracts and dashboard-app `npx vitest run`;
  - the `verify:guards` script tests (`node --test …`);
  - each guard on its own (`node scripts/guards/<g>.mjs`).
- **`guard-pgtap` is UNAVAILABLE on this Mac** (no local Postgres 15, `dpkg` not found), and `run-all.mjs` stops at the first failure. So run the remaining guards one by one, and leave pgTAP to CI.
- **Don't run local `verify:supabase`** unless the change has SQL and the shared stack is idle.
- **Workers-pool tests:** there is no local console output. Spy on `console.error` and parse JSON lines. Scheduler state leaks between owner-DO tests, so use unique DO names.
- **Owner-DO fixtures:**
  - a console runtime needs `TELEGRAM_BOT_TOKEN: '123:synthetic'`;
  - mock directory RPCs by name;
  - set the `WALDO_OWNER_TIMEZONE` fallback to a non-UTC zone so that saving the fallback shows up.
- **Read results through the app chat route, not the outbox.** `appCaller` acknowledges sends even when nothing was delivered.
- **Watching CI:** don't poll with `gh`. Use the app's PR status (`get_status`); the PR is bound to the session.
- **Mutation-check every new test** by breaking the fix one piece at a time.
