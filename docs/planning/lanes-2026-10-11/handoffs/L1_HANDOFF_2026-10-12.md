## 6. Verification and pitfalls

- Pinned pnpm: `npx -y pnpm@10.34.4 verify:guards`, full `verify` for runtime/contracts changes. Locally I used a pinned install in the scratchpad (`pnpm10/node_modules/.bin`) on `PATH`; `timeout` does not exist on macOS.
- Guards: run `scripts/guards/*.mjs` one by one; `run-all.mjs` stops at `guard-pgtap`, which needs Linux (report UNAVAILABLE locally; CI runs it).
- **The `verify` job's pgTAP gate uses `scripts/pgtap/shim.sql`, a stubbed Auth schema, not real Supabase.** A fixture or function touching `auth.*` must work in both. I added `auth.refresh_tokens` to the shim; real `auth.sessions.id` has no default (give an id in fixtures).
- Local pgTAP container (`pgtap-up.sh`) also stubs Auth: `schema_contract` (3 failures) and `waldo_owners` (1) fail identically on baseline there; CI (real Supabase) passes them. `email_confirmed_at` may be missing locally (add in the throwaway only).
- Workers vitest pool prints no console output and has no filesystem; import JSON fixtures. A full runtime run can take several minutes and shows rare load-induced 5 s timeouts (`memory-long-thread.test.ts` passed alone).
- Never touch the shared local container `supabase_db_oqcjjcytjvrckvylagsl`; the full `verify` resets shared local Supabase, so do not run it while another lane does.
- **Deploy procedure** (staging only; each step has the owner's go):
  1. AskUserQuestion with the exact SHA; re-check the tip and that CI is green at it.
  2. `git worktree add --detach <scratch>/deploy-wt <SHA>` from a clean state.
  3. Preflight (read-only): `env -i PATH=<pnpm10>:<node>:/usr/bin:/bin HOME=$HOME EXPECTED_SOURCE_SHA=<SHA> SUPABASE_PROJECT_ID=togdshayyxycitzckpqv bash -c 'export SUPABASE_ACCESS_TOKEN=$(grep "^SUPABASE_ACCESS_TOKEN=" <path-to-mvp .env> | cut -d= -f2-); node scripts/staging-migration-preflight.mjs'`. It writes `staging-migration-preflight.json` in the tree: move or delete it, the apply script refuses a dirty tree.
  4. Hosted history must be a prefix of the sorted local list, so new migrations must sort above everything applied.
  5. Worker: `env -i PATH=... HOME=$HOME bash -c 'pnpm install --frozen-lockfile; scripts/deploy-runtime.sh --env staging'`. **Always `--env staging`: without it this deploys production.** The script prints bindings including the owner id var: do not paste its log.
