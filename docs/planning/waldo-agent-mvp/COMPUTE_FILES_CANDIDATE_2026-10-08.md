## Owner outcome and concrete serving path

An authenticated owner saves/upload a CSV through existing private workspace, executes reusable argv with exact revision/path inputs using workspace_compute, reads the derived Markdown, renders a PDF/DOCX via existing workspace_render, downloads through the existing owner-authenticated delivery URL, and reopens its exact durable artifacts after interruption. The runnable CSV is an example, not a hard-coded workflow. Commands may use Node, shell and binaries in the pinned Linux image; no automatic download/install/network credential injection is added.

TelegramOwnerDO registers workspace_compute only with optional private COMPUTE binding. One import and the existing workspaceToolHandlers call supply ownerComputeExecutor scoped to immutable physical DO ID. The model selects no tenant, provider URL or operation identity. Existing workspaceOwnerHost supplies signed owner/mapping/epoch admission, per-owner R2/SQLite state, compare-and-swap writes and download authority. No index.ts, console.ts or shared serving wrangler config changes.

Current ownerEffectLedger reserves the owner invocation before provider dispatch. Its effect ID binds owner/turn/tool-call and canonical intent binds the complete validated argv/file payload. Changing args under the same call cannot issue another execution. Provider journal independently commits issued state before native execution. Unknown effects reconcile saved workspace/provider receipts only; there is no dispatch fallback after issue. Accepted result lost before save recovers into the original workspace operation; a completed workspace receipt is read back before usable delivery. /stop closes the active run, cancels native compute and prevents late artifact publication. Workspace bodies/results remain external provenance.

Limits: one isolated VM per owner+operation, lite1/16vCPU/256MiB/2GB, Internet disabled, no automatic env/credentials, input/output256KiB, logs16KiB, operation30s. Entire VM destruction handles descendants; provider DO persists a35s alarm before issue and PID1 sleep35 is secondary cleanup. Durable artifacts/receipts reopen; processes do not resume. Staging one-owner wrapper denies before namespace allocation and every HTTP path is404. No new grant, session, migration or database/security/secret changes.
