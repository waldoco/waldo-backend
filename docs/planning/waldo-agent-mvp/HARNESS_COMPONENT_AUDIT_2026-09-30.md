# Harness component audit: what earns its place

30 September 2026. Audited #378-#393 against source at e1c20143227174fd2947b16b41c6434afd1cb701, then checked the official references below. This is an audit and proposed prioritization, not deletion approval or a benchmark result. All 36 native cases remain unrun.

## Answer

The owner is right to question the build cost. Reproducible tasks, separate verification, outcome tests and saved logs are established practice. Two-user routing/effect tests are justified by Waldo's product claims. Seven role-keyed signatures, a generic timed authority layer and per-response billing equality are not universal benchmark requirements. Some useful safety tests were turned into prerequisite machinery before the first real model smoke ran. Stop expanding that machinery; get the runner to a small, inspectable smoke, and keep special-case checks with the cases that need them.

Corrections to the earlier explanation:

- We did not find evidence that Terminal-Bench, SWE-bench and HELM all use seeded fixture clocks, HMAC receipts or Waldo-style authority branches. Do not call those standard shared features.
- It is not established that other harnesses are all single-user or lack trust testing. These references simply evaluate different tasks.
- Cloudflare already isolates a DO's attached storage. Waldo's tests check that ingress chooses the right DO and provider account and that writes remain bound to the right approval. They do not supply Cloudflare's isolation.
- #390's exact per-response billed cost gate is stronger than the provider interface verified here. The OpenAI example returns time buckets/grouped usage and costs. A per-response billed-USD join must not be invented from estimates.

## The shortest justified next path

1. Implement one actual-model runner through the real webhook/DO with fictional source/provider adapters, a controlled clock where the scenario needs it, and outbound effects intercepted. Keep reference judgments away from model input.
2. Save one supervisor-owned trial bundle: selected fixture/config/version, model responses and usage, routed DO logs, source accesses, effects and final state. No new receipt service.
3. Run the selected read smoke, then approval/write smoke. Inspect useful result, tool path, forbidden effects, retries and final state. Report token usage and estimated cost honestly, not an invented provider bill.
4. Use those smoke results to unlock capability-lane merge review, not claim all 36 passed. Run the full 36 after steps 3/4 in the owner's reviewed chunks. Scope special authority/revision/second-user checks to relevant cases.

The generic distributed custody expansion, universal grant/second-owner fixture gate and unavailable per-response billing gate are the main simplification candidates. Already-merged code need not be removed indiscriminately. The immediate win is to stop treating every helper as another prerequisite project. Any changed scoring contract needs explicit tests and a documented disposition before a scored native result.

## What the current tests do not prove

Scripted model responses do not demonstrate model behavior. In-process calendar state does not demonstrate live Google behavior. A key signature does not establish independent key custody. A fetch mock does not seal all network transports. Fixture authority does not authorize production effects. No component here proves deployed staging, public-web route operation, R2 isolation or the complete shared database boundary. #394 later binds trace persistence to fixture time; it is useful bookkeeping, not another scoring standard.

## Sources inspected

Official sources fetched 30 September 2026. These are evidence of the specific practices above, not claims about every harness in the industry. Primary docs are the relevant source type for this implementation mapping; no third-party endorsement is inferred.

- **Harbor task structure**, successor format documenting differences from Terminal-Bench: https://www.harborframework.com/docs/tasks . Instruction/config/environment/tests separation, test.sh reward output, downloaded logs, network policy, optional separate verifier, trajectory artifacts and direct sidecar collection. Default verifier is shared; separate isolation is opt-in. We are not claiming every Terminal-Bench version has Harbor's current features.
- **SWE-bench evaluation guide**: https://www.swebench.com/SWE-bench/guides/evaluation/ . Prediction JSONL IDs, selected-instance runs, per-instance logs and submitted/completed/resolved distinction.
- **SWE-bench harness reference**: https://www.swebench.com/SWE-bench/reference/harness/ . Docker environments, patch application, tests, result reporting. This does not specify Waldo-style HMAC receipt custody.
- **HELM official project**: https://crfm.stanford.edu/helm/ . Benchmark families and original standardized evaluation project.
- **HELM paper**, version dated 1 October 2023: https://arxiv.org/abs/2211.09110 . Sections 1.1 and 4: explicit scenario/metric coverage, multiple metrics including efficiency, standardized conditions, released prompts/completions. Waldo's five outcome findings are not its metric definitions.
- **Cloudflare Durable Objects concepts**: https://developers.cloudflare.com/durable-objects/concepts/what-are-durable-objects/ . Globally addressed objects and attached private storage accessible only within that object; choosing the right object remains application work.
- **OpenAI Usage/Costs cookbook**: https://developers.openai.com/cookbook/examples/completions_usage_api . Usage buckets with token/request counts, grouping dimensions and cost monitoring. This inspected example does not provide the per-response billed-cost join #390 requires. It does not prove no provider anywhere could supply one, only that our current assumed interface is not grounded.
