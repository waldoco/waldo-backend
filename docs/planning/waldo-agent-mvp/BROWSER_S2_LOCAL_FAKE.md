# Browser S2: bounded synthetic form, local fake evidence

This slice exercises one controlled HTTPS form with known native semantics. It is staging-oriented, but its command transport has no live provider factory. Provider S0 proof and Core acceptance are separate gates; BROWSER remains omitted. It does not establish arbitrary website parity or protection against side effects implemented through GET.

The serving path remains `browse_act` → `browserTaskHandler` → the owner-bound browser host → existing browser task checkpoints and approval desk. The owner DO finishes each run through the host, retaining only an unexpired approval hold. `browser-gate.ts` exposes the same continuity machinery for Core acceptance tests; its approval callbacks must adapt the existing ledger rather than introduce another approval system.

The closed commands are goto, click, type, scroll, read and wait. Commands are parsed before dispatch; goto is restricted before browser IO. The host observes actual URL, element facts and form values. A single configured native submitter, default form button and form Enter are held before effect regardless of model intent or labels. Declared send widens a hold; a declared-only send is rejected without an action or approval card. Reads presented to the model contain URL, text and element references only. Password and hidden fields are refused.

The approval digest binds actual page URL, native action reference, POST destination, field names, nonsecret values, owner, run and site. The existing owner approval ledger is consumed once; replay, foreign owner, stale observation, mismatched proposal and expired approval are refused. The trusted lower transport must check the installed request policy before every request and redirect hop, reobserve immediately before effect, and invoke the synchronous current-approval assertion. Only the exact approved POST body may pass once; unsolicited POST, PUT and DELETE are refused. These obligations are proved by local fake transports only, not by page JavaScript shims or a live provider protocol.

A hold suspends host state until the fixed session deadline, capped at 600 seconds. A subsequent hold cannot extend it. Denial allows reading during the current run, then run completion closes. Expiry closes and late approval fails. Terminal paths require physical close and exact absence; unresolved cleanup prevents new allocation. Reconstructed host state must reobserve before effect; uncertain outcomes never trigger an automatic click.

Local coverage includes a complete fake owner DO journey: read, fill, plain button click, native submit hold, owner approval, one POST, receipt and exact physical absence. It also covers foreign owner, replay, denial, run completion, expiry, default/native input submitters, Enter, declared send, stale state, off-site navigation, request/redirect denial, synchronous expiry during final observation and unresolved cleanup. Core-owned executable gate tests remain a separate acceptance deliverable.

No live provider or model calls, deployment, DB reset/migration, credentials, persisted login or changes to PR881 are included. Source publication uses a coordinated draft PR; Core owns merge and deployment. Existing time, budget, grants, receipt and cleanup hooks remain in use.

Core's v3 fixture composed the real adapter and exposed three corrected source gaps: empty nonsecret values now remain exact approval facts, native input submit/image controls need no text-field mapping, and denied unsolicited page writes report a held refusal without substituting a form proposal. Strict commands still reject unknown description keys. A failure after durable submission intent remains uncertain even when a fake observes no POST; the host never retries an unknown physical outcome. Terminal closure prevents another command in the same fixed run.

Review regressions cover the nested `command.url` declaration through actual tool dispatch before handler/provider IO, including private addresses, host blocklists and strict allowlists. URI conformance traverses union branches and requires a nonempty string target. External or unassociated native submit controls are rejected as unsupported observations in this known fixture. Approval persistence/publication failures close unpublished holds; repeated reads never extend the first deadline. Owner run cleanup errors produce a structured failure record and attempt canonical revocation without masking the owner result or claiming confirmed absence.
