## Orgo source-grounded facts and cost shape

The [introduction](https://docs.orgo.ai/introduction) describes Linux browser desktops, HTTP/VNC, model-independent computer use and advertises boots under 500 ms. The [API overview](https://docs.orgo.ai/api-reference/introduction) lists screenshot, pointer, keyboard, bash, file upload/download, clone, resize and start/stop. [Instance types](https://docs.orgo.ai/guides/instance-types) say computers have dedicated resources, default 1 CPU/4 GB RAM, plan-dependent per-computer and account caps; disk/files survive stop/start, but processes and memory do not, and IP changes. [Stop semantics](https://docs.orgo.ai/api-reference/computers/stop) state stopped machines incur no compute charges, not that subscription or disk is free. [Templates](https://docs.orgo.ai/guides/templates/introduction) use golden snapshots; curated templates launch on paid plans, custom publish/build needs Scale. [VNC embed](https://docs.orgo.ai/guides/embed-vms) requires careful access control and short-lived access. These are vendor claims and API docs, not measured Waldo outcomes.

The live [Orgo pricing page](https://www.orgo.ai/pricing) lists Hacker $29/month (1 computer, 8 GB RAM pool, 40 GB storage), Startup $99 (4, 32 GB, 160 GB), Scale $399 (16, 128 GB, 640 GB), and custom enterprise. Base included capacity is $29, $24.75, $24.94 per concurrent computer-month respectively at full utilization; this is not a per-user bill. AI credits ($5/$10/$50) are bundled; bring-your-own model keys, additional computers, network and other charges need a quote. At 10,000 always-on dedicated machines the arithmetical Scale base is 625 plans x $399 = $249,375/month before enterprise discount, add-ons, model and network, but self-serve quota does not establish that this purchase is available. Bursty users cost differently. The page does not expose add-on rates or a credible per-user usage forecast.

## Bakeoff contract

Run the same representative workflow on each viable provider: (1) authenticated India-facing browser login with OTP/MFA and iPhone handoff; (2) file upload, install/build/test, then artifact export; (3) sleep/stop, resume and inspect session and disk truth; (4) prepare/approval/final external submit with response-loss reconciliation; (5) parallel owner isolation, hostile page/egress probe, credential boundary, snapshot/clone sharing controls and cleanup. Record p50/p95 boot, action and resume latency, failure modes, provider quota, complete VM/browser/proxy/model/storage bill and idle duty cycle. Compare light, typical, heavy and burst concurrency before selecting. The current [`SANDBOX_TIER_SPEC_2026-09-27.md`](./SANDBOX_TIER_SPEC_2026-09-27.md) has no-network/no-secret S1 and worker-enforced effects; any Orgo-backed tier must retain or explicitly re-spec those boundaries, never inherit trust from a VM label. Do not treat vendor performance claims as measured receipts.
