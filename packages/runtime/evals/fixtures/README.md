# Waldo-native development suite source

`Waldo_Benchmark_Cases_v2.jsonl` is the owner's original 36-record authored specification attachment from September 29, 2026. SHA256: `fc651ed0e02bf53d3875d2497637f9f9309db794b6ce02386227a04b7155211f`. It replaces the temporary atlas-derived extraction, which flattened or omitted fields. Preserve these bytes as the development source and review any future revisions separately. The W01-W24 and R25-R36 rows all carry `execution_status: not_run`.

`waldo-native-suite.ts` validates bytes and the required structural contract; its tests are source-integrity checks, not model trials, actual provider effects or results. Do not feed `authority`, `expected_behavior`, `forbidden_behavior`, `pass_evidence` or `evaluation_note` to Waldo as an owner instruction. Fixture authority is fictional. A runner still needs isolated two-owner source and provider adapters, a controllable clock, intercepted effects, real authenticated Telegram ingress, independent model runs, authoritative state and answer checks, and resets. Label any unsupported case honestly. Keep a separate unseen holdout for release decisions.

`Waldo_Reference_Judgments_2026-09-29.jsonl` is the independent benchmark lane's unexecuted 36-case reference judgment artifact, SHA256 `df5783365923212d740f6b635ff93b79e99d6f7b48536f35953c65a5736d2786`. It is paired to the original suite by ID, title, source digest, metric and pass evidence; `reference-judgments.ts` verifies the exact bytes and shape. References provide quality-bar and rubric input only, never matching tool trajectories, owner permission or observed outcomes. They have no tools, receipts or scores. A different valid agent path passes if it reaches a useful authorized outcome with evidence and no forbidden effect. W01/W20/W22/W24/R33 need explicit fixture/grading decisions before any scored run; other cases may also need source rows, approval words, provider outcomes or clocks. Keep `not_run` until a real isolated trace and independent final-state grade exist.

`grading-contract.ts` assembles a deliberately ungraded packet from a pinned case and reference. It requires runner-supplied captured bytes plus digests for fixture manifest, transcript, tool trace, authority timeline, source revisions, intercepted effects and final-state readback. Digest validity only proves the bytes were handed over; it does not authenticate provenance or score the case. W01/W20/W22/W24/R33 additionally require an evaluator-authored branch adjudication capture. `packet_prepared_ungraded` cannot be reported as a pass, a run, or a verified provider state. The eventual independent evaluator must compare useful authorized outcome, source/permission evidence and all forbidden effects, accepting different valid paths rather than matching a reference plan or tool trajectory.

`outcome-grader.ts` is an evaluator-side review aid, not a completed grader: it checks five reviewer-supplied findings against captured excerpts, returns `blocked` on missing/unknown evidence and `fail` on a cited violation. Five affirmative findings return `candidate_pass_unverified`, never an official pass, because reviewer identity, capture-chain provenance, and source truth are not authenticated by the module. R33 remains blocked until its pinned missing fixture inputs exist. No W/R result has been generated by these tests.

`isolated-capture.ts` binds externally collected bytes to two fictional identities, candidate-owner labels and expected capture roles. It does not run the model or authenticate those labels. Its passing unit test is a schema/assembly check, not a W/R trial. The real DO ingress capture, source adapter audit, clock/revision schedule, effect interception, independent provider readback and independent review remain required before any case score.

`trial-provenance.ts` adds evaluator-side HMAC receipt checks for all seven captures using separate runner, source, effect and readback keys. Keys must live outside agent/model context and be held by genuinely independent adapters; a self-signed bundle is not independent proof. It rejects wrong owner, seed, case, role, digest or missing receipts. It does not attest that a provider readback was truthful, execute the real DO trial or issue a score. This is a prerequisite, not a release gate by itself.
