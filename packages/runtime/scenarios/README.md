# Isolated ingress transport, not a benchmark runner

`isolated-telegram-ingress.ts` drives the real webhook routing and owner listener with two fictional owners, an intercepted Telegram outbox and a fresh world per trial. Its DO sink and reply callback are test doubles. The two smoke tests prove routing and capture only; they do not exercise the production owner DO, live model, source/connector adapters, permission ledger, mutable fixtures, charge sink or W/R graders. None of the 36 original cases has run. Do not report transport tests as a W/R score.

The separate `test/owner-do-ingress-isolation.test.ts` reaches the production webhook, two actual owner DOs, listener and responder under a test-only Worker configuration. Its model and Telegram endpoints are mocked. It also connects two fictional Google accounts to the isolated source world and proves owner-separated Gmail tool outputs through real DO turns; a separate proposal-only test holds the resulting calendar card open, rejects a callback from the other fictional owner, skips it, and verifies a later approve does not commit. These are read/proposal gates, not a model-quality or provider-effect score. An explicitly opted-in calendar-create stub also records a fictional provider effect only after the right owner approves a card, then asserts the approval ledger is done and a repeated approval records no second effect. The stub now commits into a separate simulated-provider calendar store and reads it back by owner; this is still the same in-process fixture, not an independent external provider oracle or actual-model trial. The owner-DO smoke now denies unexpected global fetches during each run and verifies none occurred; this guard has a direct negative test, but it does not cover every outbound transport or prove sealed actual-model execution. Next: bind the fixture clock, seal all remaining outbound transports, reset storage per trial, apply timed source/permission changes and collect authoritative final state plus model answer. Run positive and negative authority branches, repeat three independent times and keep case oracles out of the prompt. Preserve `/probe/turn` for founder-only staged smoke tests, not a multi-owner benchmark: capture mode strips live tools and suppresses memory persistence; `live:true` can make real effects.

`isolated-source-world.ts` is an additional suite-neutral source/effect substrate: independent owner namespaces, copied reads, a monotonic fixture clock with scheduled revisions, and an intercepted, idempotency-keyed effect log. Its source text cannot authorize an effect. Calendar create can now populate a separate test-provider state with owner-scoped readback and retry-key collision checks; the normal Google adapter still rejects effects, and provider state is not a native-case score. Fixture tests cover same-ID owner isolation, source staleness/reset, duplicate/colliding sends and simulated provider readback. Its Google read adapter is test-wired into the owner DO with a mocked model, and its effect log and simulated final state are checked after a fictional approval, but this does not prove authorized final state in a real provider. External official benchmark adapters must keep native task IDs, world/grader and score lines distinct from Waldo-translated cases.

`evals/fixture-authority.ts` holds the evaluator-only synthetic clock and authority snapshots. It activates timed owner branches, requires a current typed synthetic grant for permitted effects, isolates owners, rejects invalid/duplicate branch identities and resets on a new instance. The native manifest readiness filter now blocks malformed owner authority or branches outside a grant. These snapshots are not wired to the production DO or agent prompt and grant no real authority. The production DO still uses wall-clock `Date.now` in several scheduling/approval paths; a fully bound fixture clock is pending.
