# Isolated ingress transport, not a benchmark runner

`isolated-telegram-ingress.ts` drives the real webhook routing and owner listener with two fictional owners, an intercepted Telegram outbox and a fresh world per trial. Its DO sink and reply callback are test doubles. The two smoke tests prove routing and capture only; they do not exercise the production owner DO, live model, source/connector adapters, permission ledger, mutable fixtures, charge sink or W/R graders. None of the 36 original cases has run. Do not report transport tests as a W/R score.

Next: replace the fake sink with an isolated owner-DO test configuration and synthetic connector/provider world, bind an authenticated per-owner test identity, block all real outbound channels, reset storage per trial, apply timed source/permission changes and collect authoritative final state plus model answer. Run positive and negative authority branches, repeat three independent times and keep case oracles out of the prompt. Preserve `/probe/turn` for founder-only staged smoke tests, not a multi-owner benchmark: capture mode strips live tools and suppresses memory persistence; `live:true` can make real effects.

`isolated-source-world.ts` is an additional suite-neutral source/effect substrate: independent owner namespaces, copied reads, a monotonic fixture clock with scheduled revisions, and an intercepted, idempotency-keyed effect log. Its source text cannot authorize an effect. Three tests cover same-ID owner isolation, source staleness/reset and duplicate/colliding sends. It is not yet wired to the production owner DO or model, and its intercepted record does not prove the authorized final state of a real provider. External official benchmark adapters must keep native task IDs, world/grader and score lines distinct from Waldo-translated cases.
