# Isolated iMessage relay scaffold (S2)

Fixture-only source package. It starts no Mac process, opens no Messages database, holds no Apple session and exposes no HTTP listener. `IMessageTransport` is bridge-neutral; `MockTransport` is the fixture transport. `ImsgRelayTransport` exchanges strict matched JSON-RPC status frames through an injected fixture exchange. Native history/generation mapping and all native mutations explicitly refuse as unverified. No copied upstream code or new native dependencies.

`SignedRelay` verifies bounded UTF-8 bytes plus version/bridge/account/timestamp/nonce with Node HMAC-SHA256 and constant-time comparison before parsing. The account resolver supplies a trusted configured binding/key, never owner context. No credential is embedded in this package: keys in tests are synthetic. There is no default live account resolver, operational policy or transport. Each finite operational policy must carry its provenance; tests use explicitly authored synthetic bounds in `test/relay.test.ts`, not claimed provider capacity. imsg protocol reference limits are pinned separately in the S0 matrix; none is silently converted into a spool or freshness policy.

The on-disk SQLite store uses synchronous FULL/WAL and an immediate transaction for record+nonce+cursor. Admission returns only after commit; rollback or backpressure returns no successful ACK. Event identity includes bridge/account/database generation/eventId; changed raw bytes conflict. Signed heartbeats reset the saved cursor on authenticated database-generation replacement and retain old pending evidence. Old generation events reject rather than silently advance. Replay nonces are retained through the signed freshness window; expired nonces can be removed because their original signed timestamps can no longer pass admission. Event/command tombstones remain.

`flush` freshly signs unchanged raw event bytes with the account key and a nonce, bounds the callback, and removes payload only after a matching durable cloud-admission receipt. A lost ACK keeps the event pending; cloud admission must be idempotent on identity+digest. The supplied callback represents a future authenticated cloud admission endpoint, not turn processing. The test cloud is an in-memory durable-admission simulation; no real cloud endpoint is wired.

Commands require the exact trusted owner/presence/subject/bridge/account/chat binding, rechecked after probing. The draft contract now requires explicit conversationKind rather than guessing opaque GUIDs. S1 and S2 reject group bindings until S3 owner membership/audience review. Every requested native feature requires ready+verified+send probe flags; targeted operations additionally require exactTarget. Files/stickers/native voice/formatting/effects/replies each have separate gates. A compiled method list never enables a native operation.

Signature age is checked at admission, before probing. After an awaited probe, current heartbeat/key/binding and transactional command identity fence execution; signature age is not checked again. A delayed-probe fixture with a refreshed heartbeat and unchanged binding may execute after that admission-age window. Commitment expiry is a separate unresolved policy, not a claimed late-execution fence.

Accepted native command bytes, parsed intent and digest are journaled before transport execution. The transaction rechecks command identity/digest after async probing; delayed concurrent duplicates cannot execute twice. A healthy occupied account lane returns proved not_started/busy; a quarantined lane returns not_started/poisoned. There is no invisible queue or automatic retry. Only a new explicitly submitted command after a proved not_started result can proceed. Other account lanes and read/probe work remain available.

Deadline, invalid receipt, thrown transport failure or unknown native result persists quarantine. A started record found on reopen becomes unknown/still_in_flight before any execution. Late callbacks cannot clear quarantine. There is no reconciliation/clear-quarantine API: later S4 must prove exact history/GUID reconciliation before recovery. `local_recorded` never means delivered.

## Bounds and limits of proof

`maxRecords` bounds events, commands, current heartbeats and freshness-window nonce rows; `maxSpoolBytes` bounds retained event/command raw payload bytes; request/receipt/probe bytes and deadlines are separately bounded by injected policy. SQLite file/WAL overhead is not equal to the payload quota. IDs/results are also bounded in aggregate by the signed request/receipt limits. Tombstones and settled command payloads are intentionally retained, so eventual backpressure needs a later reviewed archival/retention policy. Do not claim continuous live draining or production readiness. No evidence is silently deleted to manufacture capacity.

Proof: temporary real on-disk SQLite close/reopen, actual transaction write-fault triggers, synthetic transport and crypto tests. Recovered started command is an explicitly seeded crash-state fixture; no real native process was killed. Synthetic account separation does not prove an Apple multi-account host. SQL inside this package initializes only disposable relay storage; no Supabase migration is applied. Native permissions, real Mac sleep/Apple session expiry, recipient-device readback, media security/R2, full owner routing and delivery are NOT TESTED. S3–S5 remain excluded.

Run local fixture suites: `npx -y pnpm@10.34.4 --filter @waldo/imessage-relay test`. The root `verify:node` includes this suite so GitHub's existing core verification job exercises it. No deployment/CI workflow configuration is changed.
